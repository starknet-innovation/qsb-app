# Protected Linux installation and enrollment

`install.py` installs the exact caller-pinned runtime and dispatcher manifests, verifies every listed file, refuses unlisted files/symlinks/existing targets, and publishes read-only `/source`, `/repo` aliases and `/opt/qsb/dispatcher`. A partial installation never authorizes execution; reconcile it before replacing anything. Run as the trusted root installer on an isolated host first. Installer artifacts are built by `node supervised/build.mjs` and included in Terraform's clean-source artifact manifest.

`qsb-dispatch.service` now uses a concrete credential handoff. Systemd's `LoadCredentialEncrypted` decrypts the separately provisioned `qsb-runpod-api` credential into a private service-owned directory. `credential-exec.py` validates ownership/mode/type, transfers it to a fresh anonymous FIFO on fd3, removes credential-related environment and execs the fixed dispatcher. It never accepts a queue-selected program or prints the value. Provision encrypted credentials through a trusted operator channel; do not put values in shell arguments, user data, SQS, Terraform or chat. No Secrets Manager retrieval is performed by these tools.

`qsb-watchdog@.service` owns a separate credential pipe and process per endpoint. Its protected `/etc/qsb/watchdogs/<endpoint>.json` file binds endpoint creation time, an at-most-30-minute deadline, `/run/qsb-watchdogs/<endpoint>.sock` and `/evidence/watchdog-<endpoint>.json`. Only enroll a newly created, owned disposable endpoint. The socket answers the runtime's nonce/liveness/deadline protocol with mode0600. Cleanup checks creation identity before deletion and confirms absence separately. It continues independently of the dispatcher, including cleanup immediately after an expired enrollment is restarted. Failure/unknown is never absence, provider drain or range completion. The role running these services must be trusted; encrypted-at-rest credentials are not protection against that root role.

The API remains disabled. Neither installation nor credential/socket enrollment grants transaction authorization or capability enrollment. Both the old proof endpoints and their spent fixtures are excluded from this procedure.

`validation-host.json` is a separate, temporary CloudFormation test host, not a replacement for the private Terraform production network. It pins an official Canonical x86_64 image and checksum-pinned Node22, has no inbound ports, uses SSM, and can read only exact public installation artifacts from its private S3 bucket. No provider or secret permissions are granted. Its public IPv4 permits outbound installation traffic; CPU credits use standard mode and a90-minute timer stops the instance. Stop it after collecting evidence; storage remains until explicit cleanup.

`host-validate.py` verifies downloaded archive hashes, runs actual Linux installation/credential/socket tests, tests systemd encrypted-credential delivery with a **public dummy value**, preloads the exact existing amd64 CPU images and installs the unchanged sealed runtime. It records the source commit and manifests. The dummy test is not enrollment of a real Runpod key or a real endpoint, and these checks do not establish a successful provider-backed search or mainnet readiness.
